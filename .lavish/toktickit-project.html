Overview & current state

What Lab 1 must prove, and where the repository stands right now.

What Lab 1 delivers

A running system check screen

The client renders one accessible screen that calls the API for health and the seeded category list, with explicit loading, success, offline, and empty states (client/src/App.tsx).

A thin, layered REST API

Importable Express app in server/src/app.ts with GET /api/health and GET /api/categories; process startup stays in src/index.ts.

Prisma + PostgreSQL persistence

A Category model with a repeat-safe, name-keyed upsert seed, one migration, and an isolated toktickit_test database.

Traceable, gated quality

Rubric-mapped tests plus a single final gate (bun run verify) covering Biome, Lefthook, Prisma validation, type checks, tests, and builds.

One vertical slice: React screen → proxied API → thin service → Prisma → PostgreSQL. Health is a liveness check and never touches the database.

API contract

GET /api/health 200 · liveness only 
{ "status": "ok", "service": "TokTickIT API" }
GET /api/categories 200 · seeded list 503 · store unavailable 
[{ "id": 1, "name": "Account and Access" }, { "id": 2, "name": "Hardware" }, ...]

Failure shape is a stable {"error": { code, message }} envelope; errors map to CATEGORY_STORE_UNAVAILABLE or CATEGORY_LIST_FAILED (ADR 0004).

Data model & seed

One model, one migration, four repeat-safe seeded categories.

Category model

model Category {
  id        Int      @id @default(autoincrement())
  name      String   @unique
  createdAt DateTime @default(now())
}

Defined in server/prisma/schema.prisma; migration 20260805160550_add_category creates the table. Development and toktickit_test databases share the migration and seed paths.

Seeded categories

#1 Account and Access #2 Hardware #3 Software #4 Network

seed-categories.ts uses name-keyed upsert so re-runs create no duplicates (ADR 0005).

Selected acceptance criteria from AC-01--AC-30: AC-05 blocks normal screens until
initial-password change succeeds; AC-09 preserves Ticket/Attachment ownership
through migration; AC-20 accepts only confirmed status-matrix transitions;
AC-21 limits Administrator Ticket Review to read-only data plus IT Priority;
AC-26 protects self/last-Administrator status; and AC-28 requires usable,
overflow-free desktop, tablet, and mobile screens.

Migration preserves Ticket and Attachment identity, maps Requester ownership
by normalized email, hashes generated local-only initial passwords, and verifies
counts/orphans before enforcing the new relationship. The Product Definition
of Done ties these contracts to passing tests, review, responsive inspection,
release evidence, and the single nine-part PDF; the formal-approval limitation
is stated in Part 1 rather than silently marked complete.

Issue \#77 does not add another role feature. It connects the already reviewed
authentication/Requester, IT Staff, Administrator, and Zen Green increments to
actual browser flows, evidence, review records, and release checks. The
important boundaries are:

\begin{itemize}
  \item Requester ownership comes from the authenticated session; the old Development Requester selector is absent.
  \item IT Staff may claim/reassign, change IT Priority, use the approved status matrix, post Public Comments, and add Internal Notes.
  \item Administrators may review existing Tickets and change only IT Priority from the review surface; they do not receive Queue or operational mutation controls.
  \item Browser fixtures prove visible workflows, while Supertest/PostgreSQL tests prove server authorization, migration, session, and account-safety rules.
  \item A reviewer comment, automation result, or generated artifact is not treated as human approval.
\end{itemize}
